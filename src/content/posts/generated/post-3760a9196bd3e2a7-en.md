# Foundations of Communication Network Systems

> Final grade = coursework 50% + final exam (open book) 50%
>
> Course content: network-system architectures, fundamental network technologies, and emerging network technologies

## I. Communication Network System Architectures

### 1. Understand the Systematic Ideas and Principles of Network Architecture

- Network architecture

  - What

    - A collection of the network's **layered structure**, **services**, and **protocols**
    - Content: the layered structural model, inter-layer interfaces, and protocols at each layer
  - Why

    - Mutual communication is extremely complex; layering simplifies the complex problem and divides network functions
  - Three parts of the layered structure

    - Information communication—end-to-end exchange and communication of information
    - Internetwork communication—the network-layer protocol determines the communication and routing models
      - The network layer is the core layer: it connects upper and lower layers and provides global communication and control
      - Different network layers and protocols determine different communication and routing models, as well as network communication performance
    - Data communication—the underlying communication network or system carries and transfers information for higher layers
      - Usually called the physical network, it is an independent form of network
      - It normally comprises Layer 2 and below; tunnels are also physical networks
  - OSI reference model **(abstract)**

    - Service: specifies what this layer does for the upper layer, but not how it does it
    - Interface: specifies the parameters, content, and access methods for interaction between layers
      - Service Access Point—describes the data-transfer relationship between upper and lower entities
        - An upper layer requests service from the adjacent lower layer through an SAP; the lower layer provides service upward through that SAP
        - A protocol entity provides multiple parallel services upward, with one SAP corresponding to one upper-layer entity
        - An upper-layer entity is associated with the service provided by only one lower-layer entity
      - Inter-layer communication is implemented through primitives
    - Protocol: specifies that protocols implement the service and this layer's functions, but does not prescribe a particular protocol
      - A protocol is the set of rules and conventions used for communication—a dialogue—between peer entities
  - TCP/IP reference model **(concrete)**

    - Characteristic: defines specific primary protocols at the transport and network layers and describes their details
    - Idea: the network layer uses IP to interconnect different physical networks, allowing IP packets to travel from source to destination
    - A physical network replaces L1 and L2 and covers a broader range of content:

      1. It can reduce to L1, L2, and the transmission medium in the OSI model.

      2. It can encompass a communication system, a communication network, or even a TCP/IP network.

      3. It offers more flexible and varied networking and communication capabilities than a simple transmission medium.

### 2. Understand Network Protocol Systems and Protocol Stacks

> Peer entities: entities at the same layer on both sides of a communication that run the same protocol
> Protocol: the rules governing dialogue between peer entities

- Protocol

  - Definition: a collection of rules, standards, or conventions followed by communicating parties in a computer network
  - Basic model: entity, service, dialogue
- Protocol dialogue—three elements:

  - Syntax: the format of information—what components it contains
  - Semantics: the meaning of the information and control information—the specific meaning of each component
  - Timing: the steps and sequence of information exchange
- Protocol stack

  - The collection of protocols at different layers of one node—a host, router, and so on—is called a protocol stack
  - Each layer may contain multiple **protocol entities**, each running independently and in parallel to implement that layer's functions
- Protocol system

  - Vertical structure: a device's protocol stack—the collection of protocols at each layer—describes the data-transfer relationship, or inter-layer communication: **real communication**
    - Communication between upper- and lower-layer protocol entities is called a **service**
    - Communication between upper- and lower-layer protocol entities is implemented through a **Service Access Point**
      - The entities do not know the details of each other's protocols
      - They communicate through a clearly defined interface function, the SAP
  - Horizontal structure: the peer-interaction relationships of protocols at each layer; communication between peer entities: **virtual communication**, or transparent communication
    - TCP: end-to-end dialogue using TCP segments
    - IP: hop-by-hop dialogue using IP packets
    - Link: segment-by-segment dialogue using data frames
  - Relationship between inter-layer entity communication and peer-entity communication
    - In essence, this is the relationship between real and virtual communication
    - Real communication: encapsulate layer by layer downward at the sender and decapsulate layer by layer upward at the receiver
    - Real communication is the **foundation** of virtual communication
- Protocol types

  - **Communication** protocols—primary protocols
    - Protocols that provide communication services and packet-delivery services to other entities
    - Protocols such as MAC, IP, TCP, and UDP
    - Provide multiple packet-delivery paths, using multiplexing for parallel transport of higher-layer protocol packets
    - Use packet-delivery services provided by other protocols
    - Have upward and downward channels, or interfaces
      - Use SAP notation to preserve **peer relationships**
  - **Functional** protocols—auxiliary protocols
    - Implement particular functions but do not provide communication services
    - Protocols such as ARP and ICMP
    - Generate or consume packets
    - Use packet-delivery services provided by other protocols
    - Usually have only a downward channel, or interface, and no upward one
- **Principles** for constructing a protocol stack

  - Principle 1: peer-entity principle
    - A protocol entity must know with whom it is conducting a dialogue
    - Otherwise, there is no need for that protocol entity to exist
  - Principle 2: independence of upper and lower entities
    - An entity need not care which entities are placed above its SAP
    - Note: entities at the same layer may also form an upper-lower relationship
  - Principle 3: transparent-transport principle
    - Peer entities can transfer arbitrary data, with received content equal to sent content
- Modular design

  - Even if a protocol can be designed as a complete whole, dividing it into one primary communication protocol and several auxiliary functional protocols can improve performance
  - Auxiliary protocols offer flexible ways to add to, supplement, and modify the primary protocol's functions

### 3. Understand and Master the Concept of Network Topology

- Network topology

  - An abstract representation of the composition of a network system
  - Physical topology
    - The structure formed by interconnecting network nodes
  - Logical topology
    - The structure formed by data-flow paths built on the physical topology
- Different network topologies can be constructed as needed in practice

  - Logically divide a large network into blocks—a **logical** structure

    - A network always has an owner. Interconnecting networks owned by multiple parties creates a larger network: an internetwork, or the Internet—an internetwork based on TCP/IP technology
    - Characteristics
      - Simplified topology that can also be organized deliberately
      - Strong scalability: it can span the globe or contain only a few computers
      - Network technology becomes easier to understand as intra-network and inter-network technology
    - Problems
      - Evaluating links between networks
      - Evaluating traversal within a network
  - Construct networks by function—a **functional** structure

    - An Internet service provider, or ISP, lays out network functions according to the services offered to users
      - Access network, aggregation network, core network, data-center network, and so on
  - Construct networks for a particular communication—a **communication** structure

    - Wireless LANs, wireless WANs, on-demand network-topology deployment, and so on
    - Networks built on communication systems

      - Data communication—deploy a data-transmission channel between any two points
      - Networking—deploy transmission channels and routers as needed
      - Construct the network topology on demand
- Hierarchical topology

  - Used to handle ever-growing networks
  - Routing issues:
    - Routing must also be hierarchical, and in turn influences the hierarchy of the topology
    - Intra-network, intra-domain, inter-domain, inter-area, and intra-area routing
- Internet structure

  - The Internet is a giant complex system. Its topology was once thought to be a random network, but measurements later disagreed with random-network predictions and instead showed a **scale-free network**
    - Random network: node degrees follow a random—normal—distribution
    - Scale-free network: a few nodes have very high degree—hub nodes—and the connection distribution follows a power law
      - The probability that any node connects to k other nodes is proportional to 1/k—the scale-free property
      - It tolerates accidental failures but cannot withstand coordinated attacks

### 4. Understand the Protocol Structures of Networks Using Different Communication Systems

- LTE/4G network structure

  - Comparison of 4G/5G with computer networks

    - Different network structures

      - Computer networks: many network topologies
      - 4G/5G: cellular networks
    - Different network protocol stacks

      - Computer networks: TCP/IP stack
      - 4G/5G: 4G/5G stack + TCP/IP
    - Different network-control methods

      - IP: distributed control
      - 4G/5G: centralized + distributed control
  - Network architecture: core network + access network

    - Core network: EPC—an IP-based distributed structure
    - Access network: E-UTRAN
  - Design the network structure according to requirements

    - User-data requirements
      - Convenient transmission
      - Fast resource access
      - Require a distributed architecture
    - Control-information requirements
      - Reliable transmission
      - Convenient decision-making and control
      - Require a centralized architecture
    - E-UTRAN: flat + IP-based
      - Reduces call-setup delay and user-data transmission delay
      - Facilitates direct data transfer between eNBs
    - Between E-UTRAN and EPC: eNBs connect flexibly to MME/S-GW
      - Facilitates roaming and handover
    - EPC: fully IP-based
      - Facilitates Internet access
  - Two IP layers in the protocol stack

    - The lower IP layer provides physical-network support through tunnels and better supports information services within a 4G network
    - The upper IP layer is built on the tunnel to facilitate Internet access
  - Choice of UDP and SCTP

    - Data services use IP + UDP because EPC uses wired connections and the upper layer can provide reliability
    - Signaling uses IP + SCTP mainly because signaling is not retransmitted and requires the lower SCTP layer to provide reliability

### 5. Develop Basic Network-System Architecture Analysis and Design Skills

- Deployment of network functions

  - “Good enough”

    - A function can be deployed in the network if it can be implemented completely at network level and reduce the burden on hosts; otherwise it should not be
  - “Unless necessary”

    - Implement functions in end systems wherever possible
    - Keep the network simple and forwarding fast wherever possible
    - Preserve flexibility
  - “If useful”

    - If a function implementable at an upper host layer is delegated to a lower layer, it should serve only as a performance optimization
- Three-plane network architecture

  - Transport plane

    - Provides the basic data-transfer function for carrying user services; also called the data plane or user plane
  - Management plane

    - Performs system-management functions
  - Control plane

    - Strengthens the control characteristics of network operation

## II. Communication Network Protocol Technologies

- Protocol services

  - A service is implemented through the interface exposed upward
  - Only a **primary protocol**, or communication protocol, provides a service
  - An entity exposes multiple service interfaces, using different numbers to identify different packet flows
  - An ordinary entity uses the service of only one lower-layer entity, but **network-protocol entities** and **application entities** may use services from multiple entities
- Representing semantics

  - Positional encoding **(preferred)**
    - Store information using a fixed number of bytes
      - Each item occupies a fixed position and fixed byte length
      - Encode the content of each item
    - A fixed byte position stores the content for a fixed key
      - Advantages: small footprint and machine-understandable content
    - Protocol PDU forms
      - Case 1: one protocol, one message
      - Case 2: one protocol, multiple message formats
    - Specific parameters are stored at specific positions
    - Efficient processing but difficult extension
  - Variable-length encoding
    - Represent each field with TLV—Type, Length, Value
    - An error in one L makes subsequent fields erroneous
      - Group content with TLV multiple times
    - Consider TLV encoding when content has variable length and its length varies widely
  - Textual representation
    - Represent packet fields with explicit strings, such as XML
    - Characteristics
      - Strong technical support: interpreted, backed by high-level language compiler technology
      - Highly flexible: the number and positions of fields can change freely
      - Strong extensibility: new fields can be added at any time by updating the interpreter, while old interpreters ignore unknown fields
- Protocol-interaction types

  - Unacknowledged interaction
    - Stateless interaction
    - The next message can be sent after TpT\_pTp​, so interaction capacity can reach transmission capacity RpR\_pRp​
    - Unaffected by RTT and transmission failure
    - Has a PDU error—loss—probability of PfP\_fPf​
  - Simple acknowledged interaction
    - Stateful interaction
    - The sender cannot transmit continuously, reducing interaction capacity
    - The next interaction must wait for the preceding one to finish
  - Reliable sequential interaction
    - Stateful interaction
      - Constraints: waiting, retransmission, ordering
    - A sequence of packets has a logical order and must be delivered reliably to the other party
      - Stop-and-wait protocol
      - Go-Back-N protocol
      - Selective-repeat protocol
    - Similar to simple acknowledged interaction, but with some probability of **terminating communication**
- Connection-oriented and connectionless protocols

  - Connection-oriented—circuit switching and virtual-circuit switching
    - Establish a circuit or virtual circuit from source to destination, possibly spanning circuits in multiple subnets
      - The characteristics of the entire circuit or virtual circuit inherit the worst segment among the networks
      - All participating networks should preferably have broadly similar characteristics
  - Connectionless—datagrams
    - Cannot provide reliability at Internet level
      - Strong adaptability to diverse networks
      - Supports both connectionless networks and interconnection among networks using connection-oriented technologies
  - Circuit switching
    - Establishes a dedicated path between source and destination; the channel is exclusive during communication
    - Communication has three phases: connection establishment, data transmission, and connection teardown
    - Stream-oriented; processing delay at switching nodes is very short, so the overall process has almost only propagation delay
    - Characteristics: exclusive channel, in-order arrival, short switching delay, almost no delay jitter, and low channel utilization
  - Packet switching—virtual circuit or datagram
    - Operates in packets: divides data into small packets
    - Each switching node stores and forwards each packet
    - Uses statistical time-division multiplexing and does not reserve channel resources exclusively
    - Characteristics: nonexclusive channel, high utilization, potentially high delay from store-and-forward and path selection—**transit delay**—possible packet loss, and potentially out-of-order arrival with datagram switching
- Protocol design

  - Reliability
    - What
      - Error control, flow control, sequence control
    - How
      - Connection orientation, retransmission, acknowledgment, PDU numbering, and flow-control mechanisms
  - Robustness
    - What
      - Adaptability or responsiveness to unexpected conditions or equipment failures in the network
    - IP is robust but unreliable
  - Network congestion
    - Flow control
      - Prevent a fast sender from flooding a slow receiver with packets
    - Congestion control
      - Prevent a group of senders from flooding the network with packets
    - Open-loop control—congestion prevention—and closed-loop control—congestion response
    - TCP congestion control
      - TCP's send window was originally designed for **flow control**; later extensions connected the window to **congestion control**
        - CWnd: congestion window—dynamically adjusted for congestion control
        - RWnd: receive window—the size of the peer's receive buffer, used for flow control
      - The harm caused by an oversized window is far greater than that caused by an undersized one
        - Oversized window: network packet loss causes retransmission
        - Undersized window: throughput is merely somewhat low
        - **Slow increase, fast decrease**
        - Slow start + AIMD
          - Slow start: for each ACK received, CWnd += 1; after successfully transmitting the data in a window, CWnd doubles
          - Threshold: when CWnd reaches the threshold, transition to AIMD
          - AI: after successfully transmitting a window of data, CWnd += 1
          - MD: after timeout, threshold = CWnd/2 and CWnd = 1
        - TCP Reno
          - Fast retransmit: after receiving three duplicate ACKs, retransmit immediately without waiting for timeout
            - Threshold = CWnd/2
            - CWnd = Threshold

## III. Relay and Switching Principles

- Relaying

  - Receive a PDU from one port and forward it through another
  - **Intra-protocol** relay

    - Protocol dialogue; relay protocol PDUs
    - Relay method: PDU relay
      –The protocol understands the PDU's content
      –It forwards the PDU using header information
  - Extra-protocol relay

    - Relay a DU through a relay external to the protocol

      - Relay between different protocols
    - Relay method: DU relay
      –The relay does not understand the DU's content
      –It forwards the DU using ICIx information
    - **Can implement protocol translation**
    - Conditions

      1. Implement some mapping between two address spaces—IPv4 can relay to IPv6, while MAC cannot map to PPP.

      2. Implement some mapping between the SAPs of two protocols—the relay entity must know what kind of DU it is relaying.

      3. Adapt between different maximum transmission units, or MTUs—the relay entity has no peer entity, making fragmentation and reassembly difficult.
  - The **data-link layer** always uses extra-protocol relay

    - Same-protocol relay
    - Cross-protocol relay
  - The **network layer** uses both forms

    - Intra-protocol relay—networking, routing, and forwarding within the network protocol, as in a router
      - The IP relay entity is embedded in the IP entity
    - Extra-protocol relay—moving from one network to another, as in a gateway
    - Extra-protocol relaying between heterogeneous physical networks at the network layer is equivalent to **protocol overlay**
  - **Transport-layer** communication endpoints do not relay. Transport-layer relay uses a proxy to relay application communication, as with SSH and Nginx

    - TCP relay can be understood as two TCP segments in a cascade; Nginx is a typical example
  - A **relay entity is not a protocol entity** because it has no peer entity
- Relay performance

  - Relay performance metrics
    - Throughput: packets processed per second
    - Quality of service: real-time performance, fairness, and so on
  - Main factors affecting relay performance
    - Input and output queuing delay
    - Switching-processing capacity
    - Capacity, including queue-storage and switching capacity
  - QoS: typical quality-of-service metrics
    - Transmission delay
    - Delay jitter
    - Constant traffic: guaranteed transmission rate
    - Rated traffic and minimum traffic: guaranteed transmission
- Relay path-selection algorithms

  - FIB table-lookup matching
    - Look up and match each packet in sequence—centralized serial processing
    - Algorithm performance: if each packet requires v table lookups on average, the relay system requires a lookup speed of Cv
    - Improve performance by modifying SMAC and DMAC hop by hop—increase hop count and reduce table entries
  - Ethernet-switch FIB algorithm
    - Problem: the address space is enormous, and occupied MAC addresses are sparsely distributed within it
    - The FIB stores only the MAC addresses of currently known stations
      - Source-address learning
      - Add an aging time so the FIB updates dynamically and removes stale information
    - Use HASH for fast matching
      - The FIB must still retain MAC addresses to distinguish multiple addresses with the same hash
    - Ethernet switches are **highly efficient**
      - Hash collisions can occur between different MAC addresses
      - High-capacity switching is easy to implement on 1G, 10G, and 100G Ethernet
  - IP-router FIB algorithm
    - Problem: every IP address worldwide is a potential destination, producing a very large table
    - Combine multiple techniques to improve FIB efficiency
      - Technique 1: replace destination IPs with subnet addresses to reduce the number of entries
      - Technique 2: default route
      - Technique 3: parallel search
      - Technique 4: optimize the FIB search algorithm
    - Routers have the **lowest processing efficiency** and **lowest throughput**
      - They struggle to play a central role in ultrahigh-speed internetworks
      - Deploy them at the edge of ultrahigh-speed packet-switched networks
  - MPLS-switch FIB algorithm
    - MPLS is a label-switching technology
      - A packet header has only a two-byte label field
      - A 12-bit label value and four bits of control information
    - MPLS has the **highest processing efficiency**
      - It can support packet switching in ultrahigh-speed internetworks
- Relay queuing models

  - A general queuing model includes three algorithms
    - Classification—select an input queue
    - Resources—allocate queue-buffer resources
    - Scheduling—schedule outputs
  - IQ
    - Packets first enter queues; only the head packet of each queue may enter the switching fabric for its output port
    - Suffers head-of-line blocking, HOL
  - OQ
    - Packets enter the switching fabric directly and queue at the output port
    - The switching fabric must support store-and-forward
    - Preferred
  - VOQ
    - Seeks the simplicity of the IQ switching fabric and the switching performance of OQ
    - Implements multiple virtual output queues for multiple output directions over one physical channel—one Crossbar port
      - Divides traffic at every IQ input, avoiding HOL
    - Performance approaches OQ
      - If packet flows are bursty but buffers are infinite, or packet flows arrive uniformly
  - Classic queuing algorithms
    - FIFO
    - Priority Queuing, PQ
      - PDUs enter different queues by priority. A lower-priority queue is served only when every higher-priority queue is empty; when a high-priority packet arrives, service switches to high priority “immediately.”
      - Problems
        - Overemphasis on high priority and neglect of low priority
          - Effective bandwidth depends both on packet priority and arrival rate
        - Low-priority packets may be delayed
    - Custom Queuing, CQ
      - Replaces single-priority classification with general classification and allocates an appropriate traffic quota to each queue
      - Problems
        - How should voice and data be classified?
        - A queue may have a high quota but remain short
        - Requires substantial manual configuration and adjustment
    - Fair Queuing, FQ
      - Serves each queue fairly; longer packets receive more service
      - Adjusts packet classification
        - Separate by flow and poll each queue for packets to serve
        - Fairness can be implemented by adjusting enqueue behavior
    - Weighted Fair Queuing, WFQ
      - Adds weights to FQ to allocate a defined share to each queue

## IV. IP Networking Principles

### 4.1 IP Addressing Technologies

#### 1. IPv4/IPv6 Addressing: Classification, Notation, Special IP Addresses, and Uses

- IPv4
  - Classful addressing—two levels
    - Wastes an enormous amount of address space
  - Subnet addressing—three levels
    - Generally used for Class A and Class B addresses
    - Uses a mask to determine the network address
    - Hierarchical routing: deliver to network -> deliver to subnet -> host
  - Supernet
    - Generally used for Class C addresses
    - The number of aggregated Class C networks is a power of two
    - Can be used for address applications by large organizations or for route aggregation
  - Classless addressing—two levels
    - Subnets and supernets still belong to classful addressing
    - Uses variable-length address blocks; the number of addresses in each block must be a power of two
    - Two-level addressing: prefix + suffix
      - CIDR specifies the prefix
    - Addresses sharing a network prefix can be represented by one network address—route aggregation
  - Address allocation, P35
  - A multihomed host may use IP addresses from the same network, but each router interface must connect to a different IP network
  - Special IP addresses, P43
- IPv6
  - Classless addressing
    - Hexadecimal colon notation
      - Omit leading zeros in a section—the four digits between two colons
      - Zero compression: replace several consecutive zero sections with a double colon
        - A double colon can appear only once in an address
    - Mixed notation: hexadecimal colon notation + dotted-decimal notation
    - CIDR notation: IPv6-address / prefix-length
  - Unicast addresses
    - Three kinds of unicast:
      - Global unicast: globally unique
      - Link-local unicast: unique under one switch and different from a private address. Used for neighbor interaction and link-information maintenance. Corresponds to a MAC address, which is likewise unique under a switch.
      - Local unicast: a private address unique within a subnet, corresponding to a private IPv4 address
    - Global unicast address 2000::/8
      - 2^(128/8) addresses for global public unicast
    - IPv4-compatible address 0000::/8
      - Unspecified address – ::/128
      - Loopback address – ::1/128
      - Embedded IPv4 addresses
        - Compatible address – ::/96
        - Mapped address – ::FFFF/96
    - Link-local address FE80::/10
      - Defines each network interface
      - Used for autoconfiguration and neighbor discovery
    - Unique local unicast address FC00::/7
  - Multicast address FF00::/8
    - IPv6 treats broadcast as a special case of multicast
  - Anycast address
    - Defines a group of computers sharing one address
    - A packet sent to an anycast address is delivered to the easiest-to-reach computer in the group
    - Anycast addresses are assigned from unicast address blocks
  - Three-level structure
    - Global routing prefix
    - Subnet identifier
    - Interface identifier
      - Can embed a physical address shorter than 64 bits
      - Mapping from MAC to IPv6, P57

#### 2. Principles of NAT

- Provide confidentiality for communication within an organization

  - Private network
  - Hybrid network—private network for internal communication and the Internet for external communication
  - VPN—use the Internet for internal and external organizational communication

    - Tunnel: a data channel established over the Internet
    - Security mechanisms

      - Confidentiality—security and privacy, so a third party cannot see the data
      - Sender Authentication—only authorized users can use it
      - Message Integrity—a third party cannot forge the data
- NAT

  - Private-network addresses cannot be used on the public Internet because they are not routed, so address translation is required
  - Basic NAT
    - One local address corresponds to one global address
  - Port NAT, or NAPT
    - Multiple local addresses correspond to different ports on one global address
    - Besides local mapping information, the NAT table records the IP address and port of the public host currently being accessed and the transport protocol in use
    - Cone NAT, P81
      - Full Cone NAT
        - Once a NAT port is bound, later arrivals are accepted
      - Address Restricted Cone NAT
        - Accepts packets only from previously recorded IP addresses
      - Port Restricted Cone NAT
        - Accepts packets only from previously recorded IP-address and port pairs
    - Symmetric NAT
      - Does not create one permanent binding. For different external hosts, it creates different NAT ports even when the internal IP address and port are the same.
    - Can be used for TCP load balancing
  - Limitation: communication generally must be initiated by an internal host using a private address
    - External access to an internal server requires DDNS
    - Without a public IP address, NAT traversal is required

#### 3. Resolving IP Addresses to Physical-Network Addresses

- ARP
  - Uses broadcast to learn dynamically the mapping between station IP addresses and physical addresses on a physical network
  - Uses an ARP cache for speed; clearing it periodically helps maintain dynamic updates
  - Gratuitous ARP
    - When joining a network, a host can use ARP to resolve the IP address it wants and avoid a conflict
  - ARP spoofing attacks
    - Response-spoofing attack
      - A man in the middle steals data
    - Request-spoofing attack
      - Continuous broadcasting reduces network performance
    - Mitigations
      - Static ARP
      - VLAN
      - Data encryption
- Multicast-address resolution
  - Each IP multicast address defines a multicast group
  - Use the physical network's multicast or broadcast mechanism to implement multicast on a multicast-capable physical network
  - Map the final 23 bits of the multicast IP directly to the final bits of the MAC; the first 25 bits are fixed to identify an IPv4 multicast mapping. This causes 32 multicast addresses—28-23=5 and 2^5=32—to map to the same MAC address.

#### 4. Principles of IPv6 Host-Address Autoconfiguration

- DHCP
  - **Stateful** autoconfiguration
  - C/S model that allows multiple responders, from which the client selects
  - Assigned addresses have leases, and the client may need to renew
  - A DHCP client broadcasts a DHCP request over UDP, and the DHCP server returns a DHCP reply over UDP
  - DHCP relay
    - Implements dynamic IP allocation across IP networks
  - DHCP spoofing attacks
    - Server and client have no authentication mechanism
    - DHCP Snooping
      - A switch forwards DHCP OFFER/ACK/NAK messages only from trusted ports and drops those messages from untrusted ports, thereby blocking unauthorized DHCP servers
  - Other security issues, P128
- IPv6 autoconfiguration
  - IPv6 incorporates the interface address into the IP address. Once a router supplies the prefix, **stateless** configuration can generate the IPv6 address automatically.
  - The interface address can form a link-unique address, allowing the host to broadcast a request to a router for a network prefix.

#### 5. Understand Mobile-IP Addressing Problems and Solutions

- Mobile IP, P50

  - Problem

    - IP addresses are designed for fixed networks, with the network prefix bound to the physical network
    - Address changes caused by host movement interrupt communication during network handover
  - Home address

    - Permanent address associated with the home network
  - Care-of address

    - Temporary address associated with the foreign network

### 4.2 IP Packet Delivery Technologies

#### Master the Concepts of IP-Packet Delivery and Forwarding

- Routing: find and maintain paths to every possible destination
  - Select paths to every possible destination
- Forwarding: look up the routing table to find a path to a packet's destination
  - Select a path to a particular packet destination
- Delivery: under network-layer control, the underlying physical network handles packet transmission
  - Direct delivery
    - The packet destination and the packet's transmitting interface are in the same IP network
  - Indirect delivery
    - The packet destination and the packet's transmitting interface are in different IP networks
- RIB and FIB
  - The RIB is constructed from information supplied by routing processes that execute routing protocols
  - After the best routes are selected from the RIB, they are copied into the FIB

#### Master IP-Packet Forwarding in Unicast and Multicast Communication and Their Differences

- Broadcast: within one network
  - Local broadcast: destination address = all-ones address
  - Forwarding: not forwarded
  - Directed broadcast: destination address = network broadcast address
- Multicast: across networks
  - Destination address = multicast address
  - A multicast router gathers multicast members locally and disseminates globally which multicast groups have members behind it
  - Join a specified multicast group
    - Every multicast address represents one multicast group
    - An IP entity can join multiple multicast groups simultaneously
- IGMP
  - Function: help multicast routers create and update a list of multicast-group members in each interface's subnet—local multicast-group membership information
  - Goal: allow a router to monitor in real time which multicast services exist on its networks
  - Fundamental requirements
    - How does a router learn which multicast services exist—which interfaces have traffic?
    - How does a router monitor them in real time?
  - Basic operation
    - A host actively sends an IGMP membership report to the multicast group it wants to join
    - An IGMP querier periodically multicasts IGMP query messages to all hosts and routers on the local network segment
    - After receiving the query, either Host B or Host C interested in G1 responds, depending on whose delay timer expires first. Message suppression improves efficiency: once one responds, the other need not.
  - Characteristics of multicast forwarding
    - Dynamic: membership changes dynamically
    - Directionless: forwarding loops
  - Solutions
    - Forward the same multicast packet only once: Reverse Path Forwarding, RPF
    - Forward along optimal paths: multicast tree

#### Master the Principles of IPv4/IPv6 and ICMP/ICMPv6

- IP protocol
  - Best-effort delivery
    - Try to send, connectionless, unreliable, datagram
  - Packet format, P48
  - IP fragmentation
    - The ID field identifies the IP packet. The flag field indicates whether fragmentation is enabled and whether this is the last fragment. The fragment-offset field gives the current offset—the fragment's position within the packet identified by the ID.
    - The offset unit is a byte; a packet whose length is insufficient is padded with zeros—the offset field has 13 bits while datagram length has 16 bits.
    - Core of packet switching: store and forward
      - IP packets need to be relatively small because a switch's ingress and egress performance are limited
        This increases opportunities for statistical multiplexing
    - Why use an offset rather than a number to identify a fragment? A fragment may be fragmented again during transmission, which would make numbering fail.
    - The total-length field includes the 20-byte header; offset calculation excludes the header and starts numbering at 0
  - Fragment reassembly
    - Uses a reassembly table
    - Has a time limit and discards fragments if the complete set does not arrive before timeout
- IPv6 protocol
  - Reason for IPv6: shortage of IPv4 addresses
  - Goal of IPv6: replace IPv4
  - IPv6 improvements
    - 128-bit addresses—a 40-byte header, compared with 20 bytes for IPv4
    - Basic header + extension headers, facilitating protocol extension because the basic header has fewer fields
    - Supports resource allocation through traffic-class and flow-label fields, facilitating QoS
    - Supports more security through authentication and encryption options
    - Other features: automatic discovery, automatic configuration, and so on
  - Transition from IPv4 to IPv6
    - Dual stack
    - Tunneling
      - Automatic tunnel: directly add an IPv4 header and deliver to the destination host
      - Configured tunnel: convert between IPv6 and IPv4 at the two endpoints
    - Header translation
- ICMP protocol
  - An auxiliary protocol for IP—it assists but does not solve the problem itself
  - Implemented over IP
    - Connectionless communication
    - Delivered directly to the destination station; forwarding routers along the path cannot learn the ICMP message content
  - Error-reporting messages
    - Report problems a router or destination host may encounter while processing an IP packet
    - Errors that do not produce an ICMP error message
      - An IP packet carrying an ICMP error message
      - A non-first IP fragment
      - A multicast packet
      - An IP packet with a special address such as [address removed] or [address removed]
    - An error report copies the first 28 bytes—the IP header and eight bytes of data
  - Query messages
    - Help a host or network administrator obtain particular information from a router or remote host
- ICMPv6 protocol
  - Extends ICMP to provide ARP functions, discover routers—stateless DHCP—and provide IGMP functions

#### Understand Proxy-Based Mobile IP and Its Communication Problems

- Mobile IP
  - “Two addresses,” with the goal of keeping the mobile host's externally visible IP address unchanged
    - Home address: always exposed externally and unchanged
    - Care-of address: the actual forwarding address
  - Do not place host-specific routes on unrelated routers
    - Home Agent, HA
      - Intercepts every IP packet addressed to the mobile host and forwards it to the Foreign Agent
    - Foreign Agent, FA
      - Forwards packets from the Home Agent to the mobile host
      - The mobile host can also serve as its own external agent, called a co-located care-of address
  - Mobile-IP communication models
    - FA forwarding
      - The mobile host's FA care-of address = the Foreign Agent's IP address
      - Use a tunnel to carry packets addressed to the home IP to the FA
      - Deliver at the FA using the mobile host's link address
    - Co-located forwarding
      - The mobile host's FA care-of address = the Foreign Agent's IP address; the mobile host's co-located care-of address = an address assigned by DHCP on the foreign network
      - Use a tunnel to carry packets addressed to the home IP directly to the mobile host
      - The mobile host decapsulates them itself
  - Proxy ARP and gratuitous ARP
    - The HA intercepts every IP packet addressed to the mobile host
    - Communication between the mobile host and other hosts on the HA network requires special handling because they appear to share an IP subnet—the proxy handles ARP requests
    - When the proxy router receives an ARP request for a particular host, it replies with its own physical address—the address of the receiving port
    - Proxy ARP is normally used to isolate communication between hosts in one subnet
      - In that isolated network, the router serves as proxy; in a mobile network, the HA does
      - ARP itself clearly contains security vulnerabilities
  - Double-crossing problem
    - Severely inefficient
    - A host behind the FA must traverse to the HA to communicate with the mobile host
  - Triangular-routing problem
    - Moderately inefficient
    - External communication does not take the optimal route because it must pass through the HA
  - Improve efficiency
    - A remote host binds the mobile host's home address to its care-of address
    - When the mobile host moves again
      - The HA sends an alert packet to the remote host to announce the changed binding
      - Teardown can cause problems

#### Destination-Address-Based and Label-Based Packet Forwarding

- Destination-address-based forwarding—routing table
  - Destination: network
  - Path: next hop
  - IP MASK next-hop interface
  - Routing-table size depends only on the number of networks, not on the size of each network—the number of hosts it contains
  - Every reachable specific network: directly connected and known non-directly-connected networks
    - Only the final hop knows whether the destination host exists
  - Default route
    - The forwarding path for all destination networks that do not match a specific network route
    - Functions
      - Makes the routing table smaller
      - Hides large amounts of routing information
    - Generally only hosts configure a default gateway. Configuring one on a router can cause a default-route loop.
  - Classless forwarding uses longest-prefix matching—a trie
  - Route aggregation requires every aggregated network to use the same next-hop path
    - Rational IP-address planning
    - Hides the network structure
- Label-based forwarding—MPLS
  - Label: connectionless -> connection-oriented
  - Label stack: multiple flows share one path
  - MPLS uses switching rather than routing
    - The switching table records the interface and next label and is indexed by the current label

#### Reverse-Path Forwarding for Multicast Packets

- RPF
  - Look up the unicast routing table using the source IP address
    - Packet arrives at the correct interface: forward according to the output-interface list
    - Packet arrives at the wrong interface: discard it
  - IP multicast forwarding is inverted: it focuses on where an information flow came from rather than where it is going

### 4.3 End-to-End Delivery and Network Congestion-Control Technologies

#### Understand and Master the End-to-End Service Characteristics, Protocol Functions, and Control Technologies of UDP, TCP, and SCTP, Together with Their Application-Layer Services, Communication Characteristics, Functions, and Uses

- Transport layer

  - Bridge between the application and network layers
    - IP: simple communication that improves forwarding efficiency
    - TCP/UDP: use endpoint processing capacity to improve communication quality
    - Applications: networked application systems
  - Process-to-process communication
    - Four addresses—IP addresses and ports—uniquely identify communication between a pair of processes
    - If any one address differs, the connection differs
  - Ports
    - Well-known ports
    - Registered ports
    - Dynamic ports
  - Parallel service
    - Iterative server: serial processing
      - Uses a buffer to queue requests for one-by-one processing
    - Concurrent server: concurrent processing
      - Creates multiple child processes to handle requests independently
        - Ports identify processes, so why can child processes continue to use the same port number?
          - Because four addresses uniquely identify a connection pair. Although the server's port stays the same, the source must differ—different hosts have different IP addresses, and two connections from the same host necessarily have different source ports.
          - In an operating system, a socket layer effectively sits between the transport and application layers. Data received by TCP and UDP is delivered to a socket; the scoket uses source and destination IP addresses and ports to identify and maintain distinct connections.
- UDP, P47

  - Message Delivery service
  - Enhancement to IP
    - Connectionless, unreliable, datagram communication
    - Provides transport-layer services, especially process-to-process communication
- TCP, P58

  - Stream Delivery service
  - Higher-layer application requirement: reliability
    - Process-to-process communication
    - Connection-oriented, reliable byte-stream communication
  - Problems addressed
    - Timeout-retransmission mechanism: unreliability and message loss affect TCP-segment reliability
    - Adaptive-acceleration mechanism: message arrival delay varies greatly across paths and over time, affecting TCP efficiency
    - Receive-window mechanism: messages arrive out of order across different paths
    - Congestion-control mechanism: network congestion causes burst packet loss
  - Initial Sequence Number, ISN
    - When establishing a connection, both TCP endpoints independently generate a **random** initial sequence number
    - Control segments in the connection-establishment phase have sequence numbers but a zero-length data portion
  - Acknowledgment number
    - The number of the next data byte expected; a cumulative value
  - Three-way handshake
    - The first connection-establishment message sets ack—invalid. Later, ack = received seq + 1, meaning all messages before seq + 1 have been received.
    - An ACK segment does not need acknowledgment; the next segment uses the same seq value as the ACK segment.
    - The connection-establishing SYN is a special one-byte message that requires acknowledgment.
    - DoS issue: accepting a request has a cost for the server, so a client can be impersonated to send TCP connection requests continuously to one server. SCTP can avoid this problem.
  - Push data
    - The sending process sets PSH, asking the sending TCP to transmit immediately without waiting for the window to fill
    - The receiver need not wait for more data and immediately delivers it to the application
    - PSH data still enters the receiver's buffer; PSH simply asks the receiver to process it promptly
  - Urgent data
    - The sender sets URG, inserts urgent data at the beginning of the segment data, and sets the urgent pointer to the last byte number of the urgent data
    - The receiver immediately notifies the receiving application
    - URG data does not enter the receiver's buffer—the sender also transmits it immediately—and the receiver must process it immediately
  - Four-way termination
    - Communication is bidirectional, but connection termination proceeds one direction at a time
    - The endpoint initiating teardown can close only its own send direction, while the other TCP endpoint may continue sending—a half-close
  - Flow control: sliding window, P85
    - The rwnd window is used for flow control
  - Error control: checksum, acknowledgment, dynamic timeout retransmission, P92
  - Congestion control: detect packet loss and control transmission rate, P95
    - The cwnd window is used for congestion control
- SCTP, P111

  - Provides reliable, message-oriented transport-layer service for multimedia and streaming applications
  - An SCTP association differs from a TCP connection through multistreaming and multihoming

    - Multistreaming: one association can carry data from multiple pipelines simultaneously
    - Multihoming: SCTP allows multiple IP addresses in one association, letting a server use multiple network interfaces to provide high-performance service simultaneously
  - SCTP packet: control chunks + data chunks

    - One SCTP packet can contain multiple data chunks belonging to different streams
  - Message streams

    - VT identifies an association, whereas TCP uses four addresses to identify a connection. SCTP allows multiple packets -> multiple IP addresses are allowed in one association.
    - SI and SSN implement multiple streams
    - TSN is the unified numbering scheme
  - Address ACK DoS, P125

    - 1. VT
      - The client's Init tag specifies the VT number for the server, and vice versa. This is secure against TCP-style blind DDoS because the other party must at least parse the request and respond according to the sender's Init tag before service resources are allocated. Repeated connection requests no longer occupy the peer's buffer.
      - This is a common security pattern: send something and require the other party to return a copy.
    - 2. Use a Cookie in a four-way handshake
    - The essence is to delay resource allocation so that a malicious host cannot occupy memory
  - Three-way termination: there is no half-closed state; when one party closes the association, the other must stop transmitting immediately
  - SCTP does not use ordinary ACKs to acknowledge control information, so only DATA chunks consume TSNs
  - Flow control

    - Receiver: cumTSN winSize lastACK
    - Sender: curTSN rwnd inTransit
  - Error control

    - SACK reports out-of-order and duplicate data chunks
  - Congestion control, P135

#### End-to-End Delivery Principles and Network Congestion Control in TCP and SCTP

- Congestion control
  - Congestion causes packet drops, which cause retransmissions and make conditions worse
  - Main causes
    - Arrival rate > processing rate
    - Departure rate < processing rate
  - Control strategies
    - Open loop—avoidance
    - Closed loop—response
  - Connection mechanisms
    - Connectionless service: cannot implement control effectively
    - Connection-oriented service: can implement flow, error, and congestion control
- TCP congestion control, P95
  - TCP detects congestion from packet loss
  - To reduce loss, TCP controls its transmission rate
  - A transmission timeout does not necessarily mean network congestion occurred
- SCTP congestion control, P135
  - Unlike TCP, it handles multihoming

#### Technical Principles for Reliable Transmission Without Underlying Reliability Guarantees

- The underlying network and IP provide unreliable, connectionless delivery -> use the protocol's own reliability mechanism: TCP
- Window control
  - Sequence number
  - Acknowledgment
  - Timeout-retransmission mechanism
  - Window
    - Sliding
    - Expanding
    - Shrinking
    - Closing
- Stop-and-wait protocol
  - The receiver reports receipt of every frame to the sender
  - Because the sender can have only one unacknowledged data frame at a time, stop-and-wait has low channel utilization on a long channel
- Sliding-window protocol
  - Controls the amount of transmitted data by setting the window size
    - Send-window expansion: the program processes data faster than it is received
    - Send-window contraction: the program processes data more slowly than it is received
    - Send-window closure: the receive window is full
  - Data with byte numbers outside the send window cannot be sent; data outside the receive window cannot be received
  - Error control
    - Receiver: return an acknowledgment number
    - Sender: slide the send window
  - Flow control
    - Receiver: advertise the receive-window value
      - The receiver controls flow control
    - Sender: change the send-window size
  - A **flow-control mechanism does not take effect immediately**, P90
  - Silly Window Syndrome
    - Symptom: segments carry very little data, reducing efficiency
    - Cause: the sender produces data slowly or the receiver consumes data slowly
    - Solution: sender delays transmission and receiver delays acknowledgment
- ARQ
  - The receiver returns an ACK for successfully received data
  - The sender caches every transmitted item until its ACK arrives and retransmits after timer expiration

## V. IP Routing Technologies

### Understand the Relationship Between Routing Methods and Network Structures

- Forwarding and routing, P5
  - Forwarding: data plane, local
  - Routing: control plane, global
- Routing
  - Dynamic routing
    - Proactive: continuously maintain the routing table so a task can be forwarded through a lookup as soon as it arrives, as with SDN
    - Reactive: generate a routing table only when needed. If a task arrives with no corresponding entry, find a route on the spot. This is common in wireless and mobile ad-hoc networks because maintenance overhead is low and it suits frequently changing topologies.
    - Distributed vs. centralized
  - Routing classifications
    - Destination-based
      - Shortest-path-first can cause extensive overlap
    - Flow-based
    - Policy-based
- Convergence: all routers reach a consistent understanding of the network topology
- Metric: measures the cost of traversing a network, such as hop count or bandwidth
- Autonomous System
  - The Internet is divided into many levels and multiple autonomous systems, and each autonomous system is further subdivided
  - Main reason: the Internet is too large for one routing protocol to update the routing tables of every router
  - IGP: Interior Gateway Protocol, or intra-domain routing—route selection mainly considers a metric
    - Routers within an AS exchange topology information
    - Form the **shortest** paths within the AS
    - Require no dead nodes and no loops
  - EGP: Exterior Gateway Protocol, or inter-domain routing—route selection mainly considers policy
    - AS border routers exchange reachability information about their internal networks
    - Form **reasonable** AS paths
    - Commercial relationships between ASes determine the topology
  - Three-level routing system: within one network, within an AS, and between ASes
  - Types
    - Stub AS: has only one connection to another AS
    - Multihomed AS: has multiple connections to several other ASes but can only be a source or sink of data traffic
    - Transit AS: a multihomed AS that allows data traffic to pass through

### Master the Fundamental Principles and Characteristics of Typical Intra-Domain and Inter-Domain Routing Protocols

- RIP

  - DV routing algorithm: does not need the weighted network topology; accumulates costs hop by hop to determine shortest paths
  - Exchanges routing information with neighboring gateways by broadcast
  - Cases in which a RIP response is sent

    - A RIP request is received
    - The routing table is broadcast periodically
    - A routing-table entry changes
  - Timers

    - Periodic timer, 25–35 s: used for periodic broadcasts
    - Expiration timer, 180 s: manages route validity; after timeout, sets the corresponding hop count to 16
    - Garbage collection, 120 s: continues periodic broadcasts during this interval to announce the invalid route with hop count 16
  - Problems, P51

    - Slow convergence from periodic broadcasts
    - Instability from routing loops
  - Solutions, P54

    - Triggered updates, split horizon, poison reverse, and hold-down timers
    - Do not solve the problem completely
  - Application, P61

    - Small networks
- OSPF

  - LS routing algorithm: must know the weighted network topology and calculates each shortest path independently
    - Uses Dijkstra's algorithm to calculate a shortest-path-first, or SPF, tree and update the routing table
  - Exchanges routing information with all gateways through flooding—event-driven
    - Every router should have a complete view of the internetwork
  - Link state: which neighbors are connected by a link, along with their types, weights, and on/off states
  - Network types
    - Point-to-point network
    - Transit network—broadcast multi-access network + nonbroadcast multi-access network
      - Select a Designated Router, DR, to represent the abstract router formed by the transit network
    - Stub network
    - Virtual link
  - OSPF messages, P80
  - OSPF operation, P81
    - Determine neighbor relationships
      - Hello mechanism: periodically send HELLO messages to announce presence; timeout means the neighbor is disconnected
    - Advertise link state with neighbors to every router
      - Link-State Database, LSDB, initialization
      - Link-state request
      - Network-wide link-state advertisement
        - Reliable flooding: every new LSA received must be acknowledged—explicit acknowledgment with LSA Ack or implicit acknowledgment with LSU
        - Broadcast transit network: send to the DR first; the DR informs every device on the transit network, and after receiving it they flood the LSA on their other interfaces
    - Independently calculate routes from the received link states
  - Multi-area OSPF, P87
  - Four router types, P90
  - Five LSA types, P91
  - Application, P103
    - Medium and large networks
- BGP

  - BGP messages, P112
  - BGP sessions
    - EBGP session: establish a peer relationship between border routers in two ASes
      - In an EBGP advertisement, the next hop is always the advertising router itself
    - IBGP session: exchange routing information within an AS
      - In an IBGP advertisement, the next hop remains unchanged and is the next hop from the nearest EBGP route
  - Path attributes, P117 and P122
  - Why does BGP still require internal routing? P126
    - 1. Sessions across internal routers require an IGP to establish connectivity
    - 2. Avoiding routing black holes requires the IGP to find how to reach an external route
  - Application, P133
    - Only transit ASes need BGP
- DVMRP, P168

  - Source tree and dense-mode protocol
  - Multicast routing table
- PIM

  - PIM-DM: source tree, P165
    - Dense Mode, DM: initially assume every router has multicast members
  - PIM-SM: unidirectional shared tree + source tree, P166
    - Sparse Mode, SM: initially assume no multicast members
  - Unicast routing table

### Understand Policy-Based Routing

- Policy routing, P134
  - Allocates paths according to rules rather than shortest path
  - BGP uses policy routing extensively
  - Path vector routing, P104
    - Exchanged content: network reachability within each AS
    - Peers: peer AS border routers
    - Exchange timing: triggered by events—reachability changes
    - Selective route advertisement—policy considerations
      - Advertisement: whom to tell about path information—whether “I” am willing to provide service
      - Selection: which path traffic takes
      - Typical policies: earn or save money, maximize performance, or minimize one's own bandwidth usage—hot-potato routing, P101

### Master the Fundamental Principles and Characteristics of IP Multicast Routing Protocols

- Multicast routing protocols
  - Multicast router, P139
    - Uses IGMP to collect local multicast-member information
    - Uses a multicast routing protocol to advertise multicast information
  - Multicast tree
    - Source tree: rooted at the source node, with one tree for each source
      - Described by source-node IP and multicast-group IP
      - Unidirectional tree
    - Shared tree: rooted at a designated Rendezvous Point, RP
      - Described by (\*, multicast-group IP)
      - Unidirectional shared tree + bidirectional shared tree
      - Consumes fewer resources, incurs greater transmission delay, and must be combined with other methods to build a path from the rendezvous point to the root
    - Pruning
      - Remove branches with no multicast receivers from the tree; the effect expires over time
    - Grafting
      - If a multicast receiver appears on a pruned branch, quickly reconnect that branch to the tree

### Relationship Between Unicast and Multicast Routing in Multicast Communication

- In a unidirectional shared tree, a multicast source can use a unicast tunnel or source tree to send the multicast information flow to the root
- PIM and CBT use the unicast routing table with RPF to improve flooding efficiency
