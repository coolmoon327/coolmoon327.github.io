# State Representation Learning

## Definition

Learning such an observation-to-state mapping, prior to solving the RL problem, is known in the literature as state representation learning.

Methods include autoencoders, Slow Feature Analysis, robotic priors, and simultaneously learning the reward and transition functions.

## Autoencoder

An AE cascades an encoder and a decoder and trains them using the difference between input and output as its loss. The resulting encoder can compress the input data with as little loss as possible.

In RL, a pretrained encoder can extract key information from an observation, which is then used as the state during training. Let the observation obtained by the agent from the environment be oto\_tot​, and let the state used in RL training be sts\_tst​. If the encoder is represented by the nonlinear equation z=e(x)z=e(x)z=e(x), then st=e(ot)s\_t=e(o\_t)st​=e(ot​).

The process for using an AE in SRL is as follows:

1. Explore the environment with a random policy and collect experience {ot,at,ot+1,rt}\{o\_t,a\_t,o\_{t+1},r\_t\}{ot​,at​,ot+1​,rt​}.
2. Train the autoencoder using oto\_tot​ from the experience.
3. Use the encoder as the first layer connected to the observation in RL, and do not backpropagate through this layer.

## ML-DDPG

> Munk, J., Kober, J., & Babuška, R. (2016, December). Learning state representation for deep actor-critic control. In *2016 IEEE 55th Conference on Decision and Control (CDC)* (pp. 4667-4673). IEEE.

This paper also proposes a prior-based method for state compression. In simple terms, robotic-prior methods introduce carefully designed assumptions—such as the simplicity prior, temporal coherence prior, proportionality prior, causality prior, and repeatability prior—and define loss functions for them so that states with different representational properties can be distilled from observations. ML-DDPG proposes a **predictable transition prior** and a **predictable reward prior**. In other words, it assumes that state transitions and the value function are predictable, so the extracted state contains the information needed to represent P(st+1∣st,at)P(s\_{t+1}|s\_t,a\_t)P(st+1​∣st​,at​) and P(rt∣st,at)P(r\_t|s\_t,a\_t)P(rt​∣st​,at​).

ML-DDPG is fundamentally different from an autoencoder. An AE learns to compress an observation, producing a state from which the observation can be reconstructed at minimal cost; in essence, it learns where observations differ. ML-DDPG instead aims to predict st+1s\_{t+1}st+1​ and rtr\_trt​. The sts\_tst​ emitted by its encoder can discard all information in oto\_tot​ unrelated to the **predictable priors**, and it cannot reconstruct oto\_tot​.

On the other hand, our actual problem is not the **“too many irrelevant states”** problem addressed by ML-DDPG. Almost all of our observations are valuable; their dimensionality is simply too high and needs further distillation. BECEC also uses D4PG precisely because experience is difficult to collect. Because ML-DDPG uses rewards for supervised learning, it necessarily requires many complete experience tuples {ot,at,ot+1,rt}\{o\_t,a\_t,o\_{t+1},r\_t\}{ot​,at​,ot+1​,rt​}, making it very difficult to train.

## A Scheme Suitable for BECEC

BECEC observations have a regular structure. Most dimensions come from base-station states, and every base station uses a fixed observation format. We can therefore encode each base station's observation independently using the same encoder and perform M backpropagation passes during one training step.

To address the difficulty of collecting experience, I suggest removing the pretraining stage and training ML-DDPG alongside RL:

1. Explore using RL.
2. Train ML-DDPG and update the encoder.
3. Train RL using a target encoder.
4. Soft-update the target encoder.

Parallel training clearly introduces instability because large changes in the encoder also destabilize the extracted state information. To see why, consider two state values that are both [1,2,3][1,2,3][1,2,3]. If the encoder has changed, they may have been encoded from completely different observations. I therefore tried using a DDPG-like target network in the process above. Before ML-DDPG converges, however, RL is unlikely to train well—just as an actor cannot move in the right direction before its critic converges.

Because BECEC does not need to solve ML-DDPG's **“too many irrelevant states”** problem, a plain autoencoder might work better, and training one is straightforward:

1. Pretrain the AE.
   1. Explore the environment with a random policy and record oto\_tot​ for every base station.
   2. Train the AE.
2. Train RL and reinforce the AE.
   1. Explore the environment using RL.
   2. Train RL without backpropagating through the encoder.
   3. At intervals, train the AE using ooo from the replay buffer.

Because observations collected by a random policy may not be representative—their coverage is broad but not focused—I hope to reinforce the AE while training RL.

The process above should require relatively small changes to the BECEC simulation, but adding an encoder to the D4PG framework raises resource-sharing issues. The network structure and training process must also be implemented from scratch, and ML-DDPG does not provide open-source code, so some debugging time will still be needed after the design is finalized.
